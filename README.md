# Expert Call Analyzer

Expert Call Analyzer is a grounded AI application built for analysing expert-call transcripts from the European robotic surgery market.

The application answers predefined interview-guide questions for each expert, extracts supporting quotes and timestamps, compares themes across interviews, and allows users to ask questions across the transcripts.

## Features

- Reads and parses 3 expert-call transcripts
- Answers interview-guide questions for each expert
- Extracts exact supporting quotes from the transcripts
- Shows source files and timestamps for generated answers
- Identifies common themes across expert calls
- Highlights differences in expert perspectives
- Supports natural-language questions across all transcripts
- Provides a source transcript viewer
- Avoids answering questions when sufficient evidence is not available

## Setup and Installation

### 1. Clone the repository

```bash
git clone <YOUR-GITHUB-REPOSITORY-URL>
cd expert-call-analyzer
```

### 2. Create a virtual environment

```bash
python -m venv venv
```

Activate the environment.

On Windows:

```bash
venv\Scripts\activate
```

On macOS/Linux:

```bash
source venv/bin/activate
```

### 3. Install dependencies

```bash
pip install -r requirements.txt
```

### 4. Configure the Backboard API key

Create a `.env` file in the project root:

```text
expert-call-analyzer/
├── .env
├── app.py
├── data/
└── src/
```

Add your Backboard API key:

```env
BACKBOARD_API_KEY=your_api_key_here
```

The `.env` file is excluded from Git and should not be committed to the repository.

### 5. Run the application

From the project root, run:

```bash
streamlit run app.py
```

Streamlit will start the application and provide a local URL, normally:

```text
http://localhost:8501
```

Open this URL in your browser.

## Using the Application

The application contains four main sections.

### Interview Guide

Select one of the predefined research questions. The application analyses each expert interview and presents a separate answer for France, Germany, and the United Kingdom.

Supporting evidence can be expanded to view the exact transcript quote, source file, and timestamp.

### Cross-Call Analysis

This section compares all three interviews and identifies:

- themes shared across the experts
- meaningful differences in their views and emphasis

The analysis is generated from the supplied interview transcripts rather than external information.

### Ask Transcripts

Enter a natural-language question about one or more of the expert calls.

The application answers using only information contained in the transcripts and provides supporting transcript excerpts where available.

If the supplied interviews do not contain enough information to answer the question, the application returns an insufficient-information response instead of generating an unsupported answer.

### Source Transcripts

The original interviews can be viewed directly inside the application, including speakers and timestamps.

## Architecture

The application follows a grounded transcript-analysis pipeline.

```text
Transcript Files
      |
      v
Transcript Parser
      |
      v
Timestamped Segments + Metadata
      |
      v
Grounded AI Analysis
      |
      +----------------------+
      |                      |
      v                      v
Interview Guide        Cross-Call / Q&A
      |                      |
      v                      v
Answers + Evidence     Themes / Answers
      |
      v
Exact Quotes + Timestamps
```

`parser.py` reads the transcript files and converts them into structured segments containing the expert, market, speaker, timestamp, source file, and transcript text.

`analyzer.py` sends relevant transcript evidence to Backboard for grounded analysis and maps selected evidence back to the original transcript.

`retriever.py` contains the semantic retrieval pipeline using Sentence Transformers and cosine similarity.

`app.py` provides the Streamlit interface.

## Grounding and Hallucination Reduction

Several measures are used to keep the analysis grounded:

- The model is instructed to use only the supplied transcript evidence.
- External knowledge is not used to answer transcript questions.
- Exact quotes are taken directly from the original transcript rather than generated by the model.
- Timestamps and source filenames are attached programmatically.
- The model is instructed not to infer unsupported relationships.
- Questions without sufficient evidence return an explicit insufficient-information response.

This makes important generated answers traceable back to the source interviews.

## Scaling Beyond 3 Transcripts

The current dataset contains only three short expert calls, so complete transcript evidence can be used for several analysis tasks without exceeding the model context.

For 30+ transcripts, the same architecture can be extended by:

- generating embeddings in batches
- storing transcript chunks in a persistent vector database such as FAISS, Chroma, or Pinecone
- filtering retrieval using metadata such as expert, market, and source
- retrieving only the most relevant transcript chunks before LLM analysis
- caching repeated queries and analyses

This would allow the application to scale while maintaining source-level traceability.
